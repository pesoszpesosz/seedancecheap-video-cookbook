Copy this proposed scene into the prompt field

Vertical 9:16, eight seconds, one continuous waist-low tracking shot. At 0–1 s a scuffed wheeled hard case rolls out of a service elevator. At 1–4 s an adult courier runs alongside it and gets ahead, holding a rubber doorstop. At 4–6 s the courier sets the wedge in the front wheel’s path. Keep the wheel and wedge visible as the case bumps to a stop. At 6–8 s the courier steadies the handle. End on the case still, just short of a painted floor line. Wheels rumble, one rubber thud at contact, no dialogue or music.

1. Submit the saved JSON

      

      
Save the response and its job ID. A connection failure alone does not tell you whether the server accepted the request.

      
2. Recover a response you missed

      

      
Look up the saved request first. If replay is needed, send that same ID and unchanged JSON; the documented replay returns the original job.

      
Run the offline recovery cases to see how a lost create response, a failed lookup and a ready job lead to different next steps.

      
3. Check that job

      

      
Replace vid_YOUR_ID with the ID returned by create or recovery. Space status checks, for example 30 seconds apart, and keep your application’s waiting screen tied to this job.

      
4. Download after Ready

      

      
Download within 48 hours after delivery, before the exact expiry time shown in your studio or job receipt. Check the curl exit code before opening the file. Use the local MP4 checker to decode it and compare its encoded size with your request. Play the full result to judge motion and sound. Check whether a later trim dropped audio.

      
The JSON commands require curl 7.76 or newer for --fail-with-body. HTTP errors return a nonzero exit code; their saved JSON is an error receipt, not a successful job. Windows examples use curl.exe.

After a confirmed failure

      
Look up the same job ID and check its status and any retry notice. For a confirmed failed request, the original reserved charge is restored. Check your workspace credits or balance. If the status or restoration is unclear, give support the job ID and the error shown. Keep your API key private.

      
Once the job is final and the charge is restored, check the exact recipe, format and live quote again. If you choose another paid attempt, save it under a new request ID. Replaying the old ID with unchanged input retrieves the original job. See the live status and restoration rules.
